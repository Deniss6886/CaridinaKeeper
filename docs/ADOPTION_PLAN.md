# Real-world adoption plan

CaridinaKeeper is a young public preview. This plan is for obtaining genuine keeper feedback and maintenance evidence; it is not a growth claim. Dependabot pull requests, automated test runs, and the maintainer's own activity are not counted as community adoption.

## Current baseline — 2026-09-12

- Public MIT repository and GitHub Pages preview are available.
- There are no verified external users, contributors, stars, forks, testimonials, integrations, or community references to report.
- The supported feedback channel is GitHub Issues; real aquarium backups must never be attached publicly.

## Safe pilot

1. Recruit a small number of consenting Caridina keepers through communities in which the maintainer already participates, following each community's promotion rules.
2. Ask participants to use fictional or redacted data first, export a backup, and report browser/OS plus reproducible workflow problems.
3. Provide a structured feedback issue for onboarding clarity, missing keeper context, mobile use, backup confidence, accessibility, and scientific wording.
4. Record only evidence participants explicitly allow to be public. Store no personal contact list in this repository.
5. Triage failures before expanding the pilot, especially any report involving lost data, misleading husbandry guidance, or inaccessible controls.

## Evidence policy

The readiness document may cite only public, reproducible evidence: released versions, dated maintenance activity, public issues or pull requests from people other than the maintainer, package/download statistics from their primary source, and community references with a stable URL. Anonymous claims, private messages, automated bot activity, and estimates are excluded.

## Readiness milestones

- At least two maintenance releases separated by real feedback and a documented response.
- Confirmed testing by keepers on more than one browser family and operating system.
- At least one substantive external issue, review, or contribution that changed the product.
- A public explanation of why the project matters beyond its maintainer and how Codex capacity would improve ongoing OSS maintenance.

These are internal evidence goals, not official OpenAI thresholds and not a guarantee of programme eligibility.
